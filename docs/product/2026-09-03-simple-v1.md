# XTRA Sign — Simple V1 (Product Reset)

2026-09-03. מחליף את קו המוצר של `2026-09-02-product-architecture.md` בכל מקום שבו הם סותרים.

**החלטת המוצר:** XTRA Sign היא מערכת חתימות, לא מערכת ליצירת ועיצוב מסמכים.
המשתמש מכין מסמך ב-Word/Canva/CRM, מייצא PDF, ומכאן XTRA Sign:

```
PDF → שדות → נמען → שליחה → חתימה → מעקב → PDF חתום
```

## Sitemap

```
/                בית: 2 פעולות ראשיות + 4 מונים + פעילות אחרונה
/suppliers       ספקים   (רשימה | דוחות)
/customers       לקוחות  (רשימה | דוחות)
/projects        פרויקטים (לשעבר "קבוצות" — אותן טבלאות, UX חדש)
/projects/[id]   ספקים | לידים | הסכמים | דוחות | הגדרות
/join/[slug]     דף נחיתה ציבורי להצטרפות ספקים (mobile-first, ללא login)
/agreements      הסכמים — מרכז המעקב (לשעבר /documents; redirect נשמר)
/templates       תבניות = PDF מוכן + שדות (+ שדות אוטומטיים מפרטי החברה)
/settings        ארגון | משתמשים | התראות (חדש)
/sign/[token]    חוויית החותם — ללא שינוי
```

יוצאים מה-V1 (מוסתרים, לא נמחקים): יצירה מאפס / Tiptap / Canvas / Design Agent /
XTRA AI / Fireberry Templates כ-UI / Groups כ-navigation / dashboard BI.

### Build (חדש)

| מה | פירוט |
|---|---|
| Projects metadata | עמודות additive על `groups`: `landing_enabled`, `landing_slug` (unique), `landing_config` jsonb, `notify_emails` jsonb |
| Leads | טבלת `project_leads`: org, group_id, status (new/approved/rejected), data jsonb, company_id, created/reviewed. Approve → duplicate detection → ספק מקומי + שיוך לפרויקט |
| דף נחיתה `/join/[slug]` | ציבורי, mobile-first, שדות configurable (חובה/רשות), rate-limited, honeypot; submission → Lead + התראה |
| טאב לידים בפרויקט | חדש → אשר והפוך לספק / ערוך / דחה; אחרי אישור → "שלח הסכם" |
| התראות email | `organizations.notification_prefs` jsonb (כתובות + אירועים); `notify()` שולח email מיידי (נחתם/ליד חדש/כשל) דרך InforU; digest יומי ב-cron |
| `/settings/notifications` | ניהול כתובות ואירועים; override ברמת פרויקט (הגדרות פרויקט) |
| סוגי התראה חדשים | `new_lead`, `expiring` + עמודת `link` על notifications (ליד → עמוד הלידים) |
| דוחות | טאב "דוחות" בספקים/לקוחות/פרויקט: KPIs (נשלחו/נחתמו/ממתינים/פגו/אחוז חתימה), פילטרים מתאריך/עד/סטטוס/מקור, Excel export |

## שינויי schema — הכול additive

| טבלה | שינוי |
|---|---|
| `groups` | + `landing_enabled` bool default false · `landing_slug` text unique · `landing_config` jsonb · `notify_emails` jsonb |
| `project_leads` | טבלה חדשה |
| `organizations` | + `notification_prefs` jsonb |

אין מחיקות, אין rename, אין destructive. מסד הנתונים לא עובר reset.

5. **תבניות + דוחות**: תבנית חדשה מ-PDF, שדות אוטומטיים ב-UI, טאבי דוחות + Excel
6. **Mobile QA + production verify**: 375/390/430 בדפדפן אמיתי, כל ה-flows של Definition of Done

## מונחים (עוגן)

- **פרויקט** — רשימת ספקים סביב פעילות (חודש התיירות). ב-DB זו טבלת `groups`. לא CRM; אין sync אוטומטי ל-Fireberry.
- **ליד** — submission מדף נחיתה של פרויקט. הופך לספק רק באישור.
- **הסכם** — מסמך שנשלח לחתימה (`agreements`). תמיד משויך לחברה.
- **תבנית** — PDF + פריסת שדות + שדות אוטומטיים. אין content editor.
- **מקור CRM/XTRA** — badge בלבד; נקבע לפי `crmRecordId`. מאגר חברות אחד.
